# Material-LIMS Phase 5 实施计划

> 制定时间：2026-06-05
> 范围依据：`docs/writing/2026-06-04-material-lims-brief.md` 第七节 Phase 5 定义
> 前置：Phase 4 后端 BUILD SUCCESS（5 模块已落地），但前端 P1/P2 / i18n 字典扩充尾巴未收

## 一、Phase 5 范围

按 brief 第七节 Phase 5「优化与上线」逐条落地：

1. 日志管理（AuditLog 增强：所有写接口埋点 + Admin 日志查询界面真实可用）
2. Knowledge Hub（KnowledgeDoc 后端全栈 + 文件上传 + 前端列表/创建）
3. 性能优化（Redis 缓存关键热点 + 慢 SQL 索引补齐 + 前端懒加载）
4. UAT 修复（收尾 Phase 4 前端尾巴：EquipmentRepairs CRUD、EquipmentStatus 枚举对齐、I18nList 接后端）
5. 知识库文档（部署运维手册 + 用户手册 + API 文档汇总）

## 二、各模块改动清单

### P0 UAT 修复（Phase 4 收尾）

- 前端 `EquipmentRepairs/index.tsx` 重写：真实维修单 CRUD（对接 `/api/v1/equipment-repairs`）
- 前端 `EquipmentStatus/index.tsx` 状态枚举改为 `ACTIVE/UNDER_REPAIR/DECOMMISSIONED`，与后端对齐
- 前端 `admin/I18nList/index.tsx` 接 `/api/v1/i18n/messages` 实接 + 编辑弹窗
- 前端 services 增补：equipmentRepairService、i18nService、knowledgeService、auditLogService
- i18n 字典扩充：`equipment.*` / `repair.*` / `knowledge.*` / `admin.log.*` 四类新增

### P1 日志管理增强

- 给所有"写"接口（POST/PUT/DELETE）补 `@AuditLog` 注解：Brand/RequestType/Department/Holiday/AnalysisItem/Equipment/Report/Request/EquipmentRepair
- AuditLogAspect 写 detail：把方法参数（脱敏后）序列化为 JSON 存 detail 列
- Admin LogList 前端表格：增加用户名联表展示（不只是 userId）+ 时间筛选 + 详情弹窗

### P2 Knowledge Hub

- 实体：`KnowledgeDoc`（id/title/category/fileUrl/fileSize/description/createdBy/updatedBy/timestamps）
- Mapper / Service / Controller 全套
- 文件上传走 MinIO（已在 application.yml 配置）；如未配置，走本地 `uploads/knowledge/`
- 前端 KnowledgeList 真实列表 + 上传 + 下载 + 删除

### P3 性能优化

- Redis 缓存：`@Cacheable` 加到 BrandService/RequestTypeService/DepartmentService/AnalysisItemService 列表查询，TTL 30 min
- 索引补齐：审 schema.sql，给高频字段加索引（request_no、request.status、analysis_task.engineer_id、equipment.status 等）
- 前端：路由级 code splitting（umi 默认开启）+ ProTable virtual scroll 大列表

### P4 知识库文档

- `docs/runbook/deployment.md`：Docker Compose 部署 / 环境变量清单 / 备份策略
- `docs/runbook/user-manual.md`：4 类角色操作指引
- `docs/runbook/api-summary.md`：所有 REST 端点摘要（按模块归类）

### P5 Phase 5 总结

- `docs/writing/2026-06-05-phase5-summary.md`

## 三、不在 Phase 5 范围

WOPI 真实落地（仍是 Mock URL）/ 移动端 / 实时通知（WebSocket）/ 二次审批流（仅一审）。

3. 前端 EquipmentRepairs 能创建一条维修单 → equipment.status 自动转 UNDER_REPAIR
4. Admin/I18nList 能看到 i18n 字典并新增一条
5. Phase 5 总结文档落盘
