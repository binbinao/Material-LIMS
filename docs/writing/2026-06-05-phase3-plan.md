## 二、Phase 3 实施清单（按优先级）

### P0 — 安全与认证基础

1. **`JwtTokenProvider`**：HS256 签发 / 校验 LIMS 自签 JWT，claims 含 `userId`、`roles`、`deptId`，TTL 8h
2. **`SecurityUtils`**：从 SecurityContext 获取当前用户 id / roles
3. **`JwtAuthenticationFilter`**：解析 Authorization Bearer / httpOnly cookie，注入 Authentication
4. **修改 `SecurityConfig.prodFilterChain`**：注册 JWT filter；`dev` 注入 dev user（自动 ADMIN 角色）便于无登录调试
5. **`AuthService.handleCallback`**：
   - 用 `code` POST `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token`
   - 解析 `id_token`（Hutool JWT 解码）取 `oid/email/name`
   - `findOrCreateUser` 入库
   - 签 LIMS JWT，set-cookie `LIMS_TOKEN`，重定向到前端

### P1 — Microsoft Graph 集成

6. **`GraphClientFactory`**：MSAL4j ConfidentialClientApplication，Client Credentials Flow 获取 Graph token
7. **`AzureAdSyncService.syncUsers / syncDepartments`**：调 `/v1.0/users`、`/v1.0/groups`，按 `external_id` upsert
8. **同步日志**：失败写入 `audit_log`（module=SYNC）

### P2 — 报告生成与 PDF 转换

9. **`templates/report_template.docx`**：放在 `lims-service/src/main/resources/templates/` 下（先用纯文本 docx 占位，可后续美化）
10. **`ReportTemplateService.generate(requestId)`**：用 poi-tl 的 `XWPFTemplate.compile().render()`，输出临时 `.docx`
11. **`MinioService`**：upload / download / 生成预签名 URL（dev 环境无 MinIO 时优雅降级到本地 `/tmp/lims-files/`）
12. **`WordToPdfConverter.convert(docxPath)`**：`ProcessBuilder("libreoffice", "--headless", "--convert-to", "pdf", "--outdir", outputDir, docxPath)`，失败抛 `FILE_CONVERT_FAILED`，dev 环境若无 libreoffice 命令则跳过 PDF 生成（仅保留 docx）
13. **`ReportService.createReport`**：串联 generate → upload → 写入 `file_url`

### P3 — SharePoint 集成（条件可用）

14. **`SharePointService`**：上传 docx 到 SharePoint 文档库 → 取 `webUrl + &action=edit`；下载最新版本
15. **`ReportService.syncFromSharePoint`**：download → upload to MinIO → convert PDF → 更新 `file_url / pdf_url`
16. **lock/unlock**：approve 时 checkout，revise 时 checkin

> 注：SharePoint 子模块依赖 Azure AD 真实可达环境，dev 环境通过 `azure.ad.enabled=false` 开关跳过实际调用。

### P4 — 数据权限与定时任务

17. **`DataPermissionInterceptor implements InnerInterceptor`**：覆盖 `request` / `report` / `analysis_task` 表的查询，根据当前用户角色注入 where 条件
18. **`MyBatisPlusConfig`**：注册分页 + 数据权限两个 InnerInterceptor
19. **`OverdueAlertScheduler`**：每小时扫描 `request`，按剩余天数计算告警等级
20. **`AuditLogAspect` 增强**：参数序列化 → `detail` JSON

## 三、风险与边界

- **不要求 Azure AD 实际配置可用**：dev profile 用 mock；prod 用 `@ConditionalOnProperty(azure.ad.enabled=true)`
- **不要求 LibreOffice 安装**：dev 优雅降级（仅 docx，无 pdf）
- **不要求 MinIO 启动**：dev 用本地文件系统兜底
- **不破坏现有 dev profile 的 permitAll**：JWT filter 只在 `!dev` 时生效

## 四、验收标准

- `mvn -DskipTests package` 成功（不破坏构建）
- dev profile 启动后所有现有 controller 仍 200 可访问
- prod profile 启动需要：`AZURE_AD_TENANT_ID/CLIENT_ID/CLIENT_SECRET + JWT_SECRET` 环境变量
- `POST /api/v1/reports/requests/{id}/reports`：dev 环境能生成 `.docx` 临时文件并写入 `report.file_url`
- `GET /api/v1/auth/me`：携带有效 JWT 时返回当前用户
- 数据权限：以 REQUESTER 身份调 `GET /requests` 仅返回 `requester_id = currentUser` 的记录
